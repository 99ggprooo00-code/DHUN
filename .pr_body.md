## What changed

**Recon (verified against the live origin) found that every internal
navigation link on the deployed site was dead**: the site is a GitHub project
page at `https://99ggprooo00-code.github.io/DHUN/` but its built HTML used
root-absolute hrefs, so a visitor who clicked "Features", "Interface" or
"See the interface" landed on a GitHub Pages 404. No CI gate could see it:
the browser/Lighthouse jobs served the build at a local origin root, and the
served-job resolver joined `base + href` as strings.

- [x] **W3** — Every button on every route resolves (static gates + served job, including `/app/`).
- [x] **W4** — Honest copy around the live interface; docs, verification record 30, CHANGELOG; mutation proofs for every new/adapted check.
- [x] **W5** — **The first real browser run of the mirror found it never booted: fix + gate.** The new `browser` job's first pass (website run `37864321503`) reported `#app` empty on all four viewports with *no error of any kind* — `app-web/src/js/main.js` exported `boot` without ever calling it, and the page loads the module as its only script. ## Decisions made autonomously

1. **Fix the link structure with a base path, not relative links** — the host's sub-path is fixed forever (no custom domain by decision); one `site.path` value + a rule is the smallest honest structure. Cost: none measurable; reversal: revert the one commit.
2. **Deploy the mirror through the existing site workflow** rather than a second workflow — a second publisher to the same Pages environment would race; the ADR-008 amendment records this and supersedes its B3 row 15, which was the previous session's explicit placeholder for this user decision. Reversal: drop the assembly step + CTA href in one commit.
3. **The mirror's browser gates are boot/honesty/console/overflow, not the marketing suite** — it is a JS application, not a static document; which catalogue answered (live vs sample) is recorded, not gated, because the labelled fallback is the correct behaviour. No Lighthouse/axe numbers are quoted for it.
4. **CTA copy worded around the honesty contract** — the forbidden-claim rules ban "web app"/"in your browser"/"play in the browser"; the hero line names what the CTA delivers (the interface) and the boundary (playback unproven) without a forbidden term, and the claims checker enforces that on every build.
5. **`app-web` source: one line, for the only reason it happens** — the original plan left the source untouched (wiring + README only); the first real browser check proved that impossible, because the entry module never booted in a browser. The W5 fix is a top-level `boot();` plus a comment, and a browser-free guard in `scripts/test_app_web.py` so the failure mode — invisible to the stub tests, the module graph, and every static check — is gated even before a browser is involved.
